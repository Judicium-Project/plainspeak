# Internationalization and localization

- Keep translations in separate resource files, keyed by stable IDs.
- Do not hardcode user-facing strings in components or logic.
- Use locale-aware APIs for dates, times, numbers, currency, and relative time.
- Handle plural rules with the platform's plural mechanism, not `if (count === 1)`.
- Support right-to-left text where the target language needs it: set `dir` and mirror layout.
- Preserve placeholders such as `{name}`, HTML tags, and identifiers when translating.
- Allow for text expansion. German and Finnish run longer than English.
- Flag machine-translated strings for native review when the content is legal, medical, financial, or brand-critical.
